# UI-автотесты: корзина и оформление заказа (демо-магазин ЮKassa)

Автоматизация UI-тестирования e-commerce на **Python + Selenium + pytest**.
Тесты покрывают ключевой пользовательский путь интернет-магазина — от добавления
товара в корзину до подтверждения заказа — на демо-стенде
[demo.yookassa.ru](https://demo.yookassa.ru/).

## Стек

- **Python 3.10+**
- **Selenium 4** — управление браузером
- **pytest** — тест-раннер и фикстуры
- **Allure** — отчёты о прогоне тестов
- **GitHub Actions** — CI (линтинг + автоматический прогон тестов)
- Паттерн **Page Object Model**

## Что покрыто тестами

### 1. Операции с корзиной (`test_cart_operations`)
- добавление товара в корзину и проверка счётчика;
- увеличение количества товара;
- добавление второго товара;
- проверка, что оба товара присутствуют в корзине;
- удаление всех товаров;
- проверка, что корзина пуста и счётчик обнулился.

### 2. Оформление заказа (`test_checkout_process`)
- переход на страницу оформления заказа;
- проверка модального окна авторизации и его содержимого (поля email, пароль, кнопка «Войти»);
- **негативные проверки** ввода города доставки (пустое значение, цифры,
  спецсимволы, несуществующий город) с проверкой сообщений об ошибке;
- ввод телефона и корректного города;
- проверка, что выбор способа доставки корректно увеличивает сумму заказа;
- ввод имени клиента и подтверждение заказа.

## Архитектура

Проект построен по паттерну **Page Object Model**: логика взаимодействия со
страницами вынесена из тестов в отдельные классы.

```
bbe/
├── pages/
│   ├── base_page.py          # базовые действия: поиск, клик, ввод, ожидания
│   ├── start_page.py         # главная страница и добавление в корзину
│   ├── cart_page.py          # операции внутри корзины
│   └── order_status_page.py  # оформление заказа
└── tests/
    ├── conftest.py           # фикстуры драйвера, скриншот при падении теста
    └── test_add_to_cart.py   # тест-сценарии
```

Особенности реализации:
- **явные ожидания** (`WebDriverWait` + `expected_conditions`) вместо статических пауз;
- **автоматический скриншот** при падении теста, прикрепляется к Allure-отчёту;
- структурирование отчётов через `@allure.epic / feature / story / severity` и `allure.step`.

## Запуск

```bash
# 1. Клонировать репозиторий
git clone https://github.com/Golubovskaya/Auto-project.git
cd Auto-project

# 2. Создать и активировать виртуальное окружение
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Запустить тесты
pytest bbe/tests --alluredir=allure-results
```

> Нужен установленный **Google Chrome**. Драйвер Selenium 4 подтягивает
> автоматически (Selenium Manager).

## Отчёты Allure

```bash
# установить Allure CLI (пример для macOS)
brew install allure

# сгенерировать и открыть отчёт
allure serve allure-results
```

## CI

При каждом push и pull request в ветку `main` GitHub Actions:
1. устанавливает зависимости;
2. проверяет код линтером `flake8`;
3. запускает тесты и сохраняет Allure-результаты как артефакт сборки.
